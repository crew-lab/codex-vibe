# ADR 0008: optional Antigravity CLI execution backend

Status: owner-approved on 2026-10-17; implemented on main; ships in 2.1.0 off by default behind `experimental.antigravity = true` (owner decision 2026-10-19); experimental until the target checks in [docs/target-acceptance.md](../target-acceptance.md#antigravity-backend-probes) pass.

vibe-app-server (pinned to Vibe 2.26.1) remains the default engine (`backend = "app-server"`). Following the owner's 2026-10-17 decision, Google Antigravity (`agy` CLI, pinned to `agy 1.4.0` and binary SHA-256) is supported as an optional second execution backend selected by `backend = "antigravity"` (with optional `paths.antigravity`, defaulting to `"agy"`). Both configuration keys are boot-bound: modifying either surfaces `boot_drift` and requires a server restart.

The Antigravity backend maintains defense-in-depth across four mandatory isolation layers:

1. **Process & Environment Isolation**: Each run executes in throwaway per-run `antigravity-home` and `antigravity-tmp` directories inside the run root, cleaned up at completion or recovery. The child environment is strictly filtered by `buildChildEnvironment`, with `AGY_CLI_OSC7501=off` and no inheritance of user credentials, history, or extensions. The child process is monitored by the supervisor's process reaper (`startReaper`) and inactivity watchdog, and untrusted workspace extensions (`.gemini/`, `.agents/`) are refused before spawn.

2. **Pre-Seeded CLI Settings (`settings.json`)**: Before spawning `agy`, the supervisor writes `$HOME/.gemini/antigravity-cli/settings.json` enforcing `toolPermission = "strict"`, `enableTerminalSandbox = true`, and `allowNonWorkspaceAccess = false`. Permissions use `agy 1.4.0`'s validated unified rule syntax: `permissions.allow` grants `read_file(<workspace>)` and `read_file(<workspace>/**)` (plus `write_file(...)` in `edit` mode), while `permissions.deny` blocks `command(*)`, `mcp(*)`, `read_url(*)`, `execute_url(*)`, and `write_file(*)` in `review` mode, alongside path-denial rules for `.git/**`, `.vibe/**`, `.gemini/**`, `.agents/**`, secret patterns, and configured `excluded_globs`.

3. **Deterministic `PreToolUse` Command Hook (`pre-tool-hook.mjs` + `hooks.json`)**: Registered in `$HOME/.gemini/config/hooks.json` under `supervisor-policy-gate`. Every tool invocation is intercepted before execution and validated against active step/turn limits (`maxTurns`, `maxModelCalls`), the active profile tools (`view_file`, `read_file`, `list_dir`, `find_by_name`, `grep_search` in review mode; plus `write_to_file`, `write_file`, `replace_file_content`, `multi_replace_file_content`, `edit_file`, `edit` in edit mode; refusing `sed_file`, `notebook_edit`, `run_command`, and external network tools), and path boundaries via `judgeWorkspacePath`. Out-of-workspace, reserved, secret, excluded, or over-limit calls are denied before execution (`{"decision":"deny","reason":...}`). Every decision appends an entry to `hook-ledger.jsonl`, finalized as `artifacts/approvals.json` for audit bundles.

4. **Mandatory Zero-Inference Preparation, Unsupported-Ceiling Rejection & Live Stream Enforcement**: Every ordinary start requires a matching `passed` receipt from `vibe-supervisor prepare check` bound to the candidate and the verified `agy 1.4.0` binary SHA-256 digest; there is no fallback when the receipt is absent. Because `agy 1.4.0` only reports token totals in the terminal `result` envelope after execution and does not report USD cost, `max_cost_usd` (`reason: "price_unavailable"`) and `max_tokens` (`reason: "token_ceiling_unsupported"`) are rejected before dispatch. During execution, `stream-json` `step_update` envelopes distinguish turns (`stepIdx`, `num_turns`) from model calls (`planner_response` steps) and immediately terminate the worker (`stop_reason: "turn_limit"`) as soon as `max_turns` or `max_model_calls` is breached.
