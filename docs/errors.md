# Error codes

Generated by `npm run docs:errors` from `REMEDIATION` in `src/contracts.ts`; do not edit by hand.

An error carries `code`, `message`, `remediation`, `retryable` and sometimes `details`. `retryable` is `true` only when the failure is transient; every other code reports `false` unless the backend marks it otherwise. Failures that are not supervisor errors reach the client as `VSUP_INTERNAL` without detail.

When `retryable` is `false`, do not resend the same task with the same limits: the same input fails the same way. Change what the remedy names (the task, a limit, the configuration or the environment) and start one new run deliberately; the supervisor never retries or replays on its own.

| Code | Meaning | Remedy | Retryable |
|---|---|---|---|
| `VSUP_AUTHORIZATION_INVALID` | No unexpired locally registered grant matches the exact dispatch inputs, or those inputs could not be bound safely. | Register the reviewed dispatch using task authorize under the selected configuration and use its unexpired matching authorization_id and attempt_id. When details.differing_fields is present, it names what differs from the registration: request fields (task, limits, context_files, review_content and the like) mean the start must repeat the registered request exactly; runtime fields (candidate, node_executable, node_version, platform, pin_manifest, policy, backend) mean task authorize ran with a different install, Node or configuration than the MCP server. Readiness alone does not authorize a task. | no |
| `VSUP_ATTEMPT_CONSUMED` | This authorization-bound dispatch attempt was reserved previously and cannot be reused, including after a failure or restart. | This attempt cannot be retried. Preserve its evidence; another start requires a fresh direct owner authorization and a newly registered attempt. | no |
| `VSUP_CONFIG_INVALID` | The selected configuration file is missing, unsafe (symlinked, foreign-owned, group/world-writable or over 1 MiB), cannot be parsed, or has a missing or invalid field. | Correct the reported config.toml field and try again. | no |
| `VSUP_VIBE_NOT_FOUND` | The Vibe executable, the vibe-app-server executable or the interpreter named on the first line of its script is missing. | Install Vibe or set paths.vibe to its executable; the vibe-app-server executable must sit next to it or be set as paths.app_server. | no |
| `VSUP_VIBE_VERSION_UNSUPPORTED` | The installed Vibe is not the pinned version, or its installed files do not match the pin manifest (details.reason names the failed check). | Install exactly the supported Vibe version (for example `uv tool install mistral-vibe==3.0.2`) or set paths.vibe to its executable; for a pin-manifest failure (details.reason) check paths.vibe_pin_manifest and write the manifest on this machine with `vibe-supervisor pin-manifest`. | no |
| `VSUP_ANTIGRAVITY_NOT_FOUND` | The Antigravity CLI executable (agy) is missing or could not be found on PATH or at paths.antigravity. | Install Antigravity CLI (agy) or set paths.antigravity to its executable. | no |
| `VSUP_ANTIGRAVITY_EXEC_FAILED` | The Antigravity session failed during execution. | Inspect Antigravity diagnostics and start a new run. | no |
| `VSUP_AUTH_REQUIRED` | Vibe reported a missing or rejected credential (401, unauthorized, missing API key). | Sign in to Vibe or configure its supported authentication. | no |
| `VSUP_WORKSPACE_INVALID` | The workspace or a context file does not exist or lies outside every allowed root, contains project .vibe, a symlink or non-directory .agents, a symlinked .vibeignore or glob characters in its path, or an edit run did not start at the git repository root; details.unavailable_root names an allowed root whose directory no longer exists. | Provide an existing workspace directory under an allowed_workspace_roots entry (the git repository root for an edit, without project .vibe, unsafe .agents paths or glob characters), and existing context files inside it; a real .agents directory is supported without inheriting its content. Add the workspace to the selected config with `node dist/cli.js allow --config <selected-config> <workspace>` (or the equivalent installed executable path). The connected server rereads that file before every readiness check and start, so no restart is needed; confirm with vibe_status in workspace mode. | no |
| `VSUP_WORKTREE_CREATE_FAILED` | git worktree add failed for the edit run; details.stderr_tail and details.operation say why. | Check the repository state and worktree path, then retry. | no |
| `VSUP_GIT_REQUIRED` | The git executable is missing, or the workspace is not a Git repository. | Install Git (the git executable must be on PATH) and use a Git repository for edit runs. | no |
| `VSUP_BACKEND_CRASHED` | The Vibe process exited before the turn finished. | Inspect the run's diagnostic events and start a new run. | no |
| `VSUP_TIMEOUT` | The run deadline elapsed, or a Git operation exceeded its limit: 30 s for queries, 5 min for worktree creation, patch export and cleanup (details.operation names it, details.kind is `timeout`). | Increase the timeout or simplify the task, then start a new run. For a Git operation that exceeded its limit (30 s for queries, 5 min for worktree creation, export and cleanup), check the repository size and disk speed. | no |
| `VSUP_RATE_LIMITED` | Vibe or its provider answered with HTTP 429. | Wait for the service rate limit to clear and retry. | yes |
| `VSUP_CANCELLED` | No longer emitted. Kept so saved run records from older versions still read; this release records a stopped run as `cancelled` with no error. | Start another run if more work is needed. | no |
| `VSUP_OUTPUT_LIMIT` | The run exceeded an event, transcript or artifact byte limit, or a Git command produced more than 100 MiB of output. | Reduce the requested output or increase the configured limit. | no |
| `VSUP_ARTIFACT_ERROR` | A run artifact could not be written, read or exported, including a Git failure while capturing the edit snapshot (details.operation), a refused Git filter, or a worktree directory that no longer exists (details.kind `workspace_missing`, details.path). | Inspect the run directory permissions and available disk space; for a Git failure, see details.operation and the repository state. | no |
| `VSUP_INVALID_ARGUMENT` | The tool arguments failed schema validation. | Correct the tool arguments and try again. | no |
| `VSUP_NOT_FOUND` | No run with that ID exists. | Check the run ID and try again. | no |
| `VSUP_BACKEND_ERROR` | The backend reported a failure that has no more specific code. | Inspect backend diagnostics and retry if the problem is transient. | no |
| `VSUP_LIMIT_EXCEEDED` | The owning server/storage instance already has an active run. | Wait for the active run to finish, then start another run. | no |
| `VSUP_NO_PROGRESS` | A running worker emitted no event for limits.worker_progress_timeout_seconds, so the supervisor ended the run. | The worker produced no output for the configured limits.worker_progress_timeout_seconds; inspect the run diagnostics and events, then start a new run deliberately; the task is never replayed. | no |
| `VSUP_INVALID_STATE` | The action is not valid in the run state, the supervisor is shutting down, or an isolated session path is unsafe. | The request conflicts with the current state: check the run status and use an action valid for it, or wait until a shutting-down supervisor has been restarted, or inspect the isolated session path named in the message. | no |
| `VSUP_STORAGE_ERROR` | A filesystem fault (disk full, permissions, read-only, I/O) hit the data directory. | Check the supervisor data directory permissions and disk space. | no |
| `VSUP_INTERNAL` | An unexpected supervisor failure; the detail is only on stderr. | Inspect supervisor diagnostics and retry; report the error if it persists. | no |
| `VSUP_RESTART_REQUIRED` | The selected configuration, reread before a readiness check or start, changes a boot-bound setting (a path, retention or a limit) that the running server cannot adopt. | A boot-bound setting (paths.vibe, paths.app_server, paths.vibe_pin_manifest, retention or limits) in the selected config differs from the value this server started with, so new starts are refused rather than partially adopted. Revert the setting, or close any active run and deliberately restart the Codex MCP server; allowed_workspace_roots changes never need a restart. | no |
| `VSUP_OWNER_LOCKED` | Another live supervisor owns the data directory (or isolated session), or its owner lock is unsafe, malformed or being recovered; details.lock_path and details.owner_pid say which. Stop the other process or give each Codex session its own VIBE_SUPERVISOR_HOME, then retry; for an unsafe or malformed lock, inspect the file named in details.lock_path. | no |
| `VSUP_PREPARATION_TIMEOUT` | A readiness check or start exceeded its 30 s preparation deadline (configuration reread, workspace validation or base resolution); no run was created. | Preparation did not finish within its fixed deadline and no run was created. Check that the workspace, repository and configuration filesystems respond, then check readiness again. | no |
| `VSUP_READINESS_RECEIPT_INVALID` | A start carried a readiness_receipt that is malformed, altered, expired, from another server instance, or bound to a different policy revision, operation, workspace or base_ref, or whose edit base no longer resolves or resolves to another commit; details.reason names which. | No run was created and nothing was launched. Call vibe_status with workspace and operation on this same connection, resolve any blockers, and start once with the new readiness_receipt; do not retry the start automatically. | no |
| `VSUP_BUDGET_EXCEEDED` | The daily budget limit for the workspace root has been reached. | Increase budgets.<root>.max_cost_usd_per_day in config.toml or wait until earlier runs age out of the 24-hour rolling window. | no |
