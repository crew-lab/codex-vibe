# Version-matched preparation kit

Each candidate ships a separate preparation-kit-VERSION directory with the conformance procedure, exact no-inference script, candidate identity and checksums. Keep this directory with its candidate archive.

Packaging captures the candidate identity immediately after `npm pack`, before regenerating the external SBOM. Its final gate installs that exact archive into a temporary private prefix using the populated offline npm cache and disabled lifecycle scripts, then compares the installed candidate identity, package version and conformance-script hash with the kit and verifies every kit checksum. Packaging announces success only after that gate passes; its delivery checksum manifest includes all kit files. The temporary installation is removed on success or failure. The external SBOM remains a separate delivery artifact: generating it later must not change the archive-to-kit binding.

Run `vibe-supervisor prepare check --kit /absolute/preparation-kit-VERSION --config /absolute/config.toml` using the installed candidate. It verifies kit/script/candidate hashes, then runs the review and edit initialization checks once with a fixed fake key and refusing network observer. It never sends turn/start or uses real provider credentials. A deterministic failure stops the check; do not blindly retry the unchanged candidate.

When `backend = "antigravity"`, `vibe-supervisor prepare check` verifies the configured Antigravity executable (`paths.antigravity`, defaulting to `agy`), requiring exact version `agy 1.4.0` and recording its binary SHA-256 digest. It generates isolated review and edit environments with private `HOME`/`TMPDIR`, validates unified permission rules in `settings.json`, and verifies the `supervisor-policy-gate` configuration in `hooks.json`. It runs zero-inference slash-command read-backs (`/config`, `/hooks`, `/permissions`, `/skills`) against a refusing loopback proxy, and executes synthetic `PreToolUse` hook evaluations covering allowed workspace access, excluded globs, reserved directories, secret patterns, and off-profile tools. It then runs the [agy probes](target-acceptance.md#antigravity-backend-probes) through agy itself, with the same fake key and a scripted loopback model in place of a provider: the hook is invoked and its deny honoured, a hook that times out, exits non-zero or prints unparseable output denies, agy's stream tool events match the audit parser, agy sends its inference traffic through the refusing proxy, and project configuration planted above the workspace is not loaded. Each must pass, or the receipt fails; the report records them under `agy_probes`. The backend must also be enabled with `experimental.antigravity = true`. The resulting receipt and sanitized report are saved in the supervisor data directory, binding candidate distribution bytes, the `agy 1.4.0` binary SHA-256 digest, Node version, platform/architecture and policy.

A private receipt and sanitized report are saved beside the selected pin manifest. Evidence binds candidate distribution bytes, pin manifest, Node version, platform/architecture and policy except workspace roots. Changing only task roots can reuse evidence; version/runtime/policy changes invalidate it. Missing, failed, changed or stale evidence blocks ordinary AppServer dispatch. Fixture tests inject their own preparation evidence provider; there is no production environment bypass. The receipt is rewritten as failed before the check launches, so an interrupted check never leaves an earlier PASS current.

Readiness reports workspace_eligible separately from eligible, candidate identity and preparation status. An optional expected_candidate SHA-256 detects connection drift. Existing runtime pin validation still runs at dispatch; an initialization-only receipt does not prove hosted inference, effective hosted permission enforcement, thinking behavior, disconnect soak, fresh-account installation or Intel support.

Review report.json/diagnostics and conformance findings before hosted testing. Hosted work retains its separately bounded allowance. A preparation failure is infrastructure evidence and must not trigger Luna fallback or replay the original task.
