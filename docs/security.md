# Security model

The supervisor limits access through canonical allowed roots, strict private data directories, minimal child environments, managed process groups, bounded streams, redaction, and explicit run-state transitions. Edits execute in detached worktrees. Export writes and re-reads `diff.patch` and checks its size and SHA-256 digest. Cleanup checks the saved patch digest, the registered worktree and git root, a fresh export compared section by section, and ignored-file status; `changed-files.json` is not compared. Changed or ignored content causes cleanup to refuse.

On hosts that deny process-group signaling, shutdown falls back to signaling the supervisor's direct child only. In that case the direct child is managed, but cleanup of its process group/grandchildren remains unverified and must not be reported as fully confirmed.

These are application controls. There is no kernel sandbox, syscall filter, network namespace, or guarantee against vulnerabilities in Vibe, Node, Git, plugins, or the host. Treat delegated work as code execution with the permissions of the local account. Shell and network tools are off and have no switch. Do not place credentials in task text or workspace files. The programmatic task is handed to the launcher shim through a private 0600 file that is deleted before Vibe starts, so it does not appear in the OS-visible process arguments.

A real project `.agents` directory can remain in the source checkout and edit worktree. The pinned shim disables project configuration discovery on the harness manager class, including session copies and reload, before either backend starts. Its exact source hash and property signatures are checked before applying the patch; drift fails closed before credential lookup. The `.agents` file-tool denylist and grep exclusions remain intact. Root `.vibe`, symlink or non-directory `.agents`, and unsafe `.vibeignore` paths remain refused. Coordinator-supplied task instructions remain the worker's explicit project contract; automatic project AGENTS.md injection is disabled.

The browser-login credential is resolved inside the pinned launcher shim, never in the Node supervisor. Only real runs (`start` and `recover`) pass the original HOME in `VIBE_SUPERVISOR_ORIGINAL_HOME`; probes never do (`createVibeChildProfile`'s `forwardOriginalHome` option), so probes make no Keychain lookup; the shim validates the Vibe version and signatures first, takes an explicit nonempty `MISTRAL_API_KEY` as authoritative (empty counts as absent), and otherwise runs `/usr/bin/security find-generic-password -a MISTRAL_API_KEY -s <service> -w` for `ai.mistral.vibe` then `vibe` with only `HOME` and `PATH`, a 5 second timeout, an 8 KiB output cap, and discarded stderr. The original-HOME variable is removed before Vibe starts; the credential lives only in the Vibe process environment, and the shim's stderr and native history filtering replace the exact value. This is an application control, not a sandbox.

Streamed message text passes through a bounded streaming redactor. A line longer than its pending limit (64 KiB) is no longer discarded: the pending buffer is redacted and all but the last 4096 characters are emitted, and the tail stays pending so a secret straddling the cut is still caught (provided it is shorter than that tail). An unfinished PEM private-key block is never cut; one larger than the limit is emitted as a single `[REDACTED]` and its remaining lines are dropped up to the end marker, after which later content flows normally. Besides bearer tokens, common key prefixes, `key=value` pairs and authorization headers, the patterns cover prose such as `API key: <value>` or `API key is <value>` (the value must look like a token of 16 or more characters, so "API key is required" is untouched), `x-api-key` headers and `*_API_KEY=<value>` assignments such as `MISTRAL_API_KEY`, because a credential resolved inside the launcher shim is unknown to the supervisor's sentinel list and could otherwise surface in a backend error message. Pattern redaction is best effort. The streaming redactor keeps a bounded suffix so secrets split across chunks are joined before emission.

A stderr tail (ACP probe, `doctor`, git failures, probe errors) is built by redacting the whole collected buffer first and only then taking the last 1 KiB, so a window that starts inside `Bearer <key>` or in the middle of a key cannot expose the rest of it. The child's `MISTRAL_API_KEY` is passed as a known secret wherever a probe, start or CLI diagnostic redacts stderr, so a bare key with no recognizable shape is caught too. When the collected buffer was itself cut (the probe keeps the first 4 KiB, git the last 4 KiB), the dangling partial token or line at the cut is dropped.

Persisted events and JSON are sanitized recursively; reasoning/private thought fields are omitted. Raw protocol streams are consumed internally and must not be logged. Patch files are not rewritten for redaction because that corrupts diffs. Export instead refuses a patch whose added lines hold a high-confidence credential and preserves the worktree for inspection. Only lines inside diff hunks that start with `+` are scanned (a content line beginning `++` included); file headers, context and removed lines are ignored. Refused shapes: a Bearer token of 20 or more characters, an `sk-`, `ghp_`-family or `github_pat_` token, an AWS `AKIA`/`ASIA` key, a PEM private key header, a configured key sentinel, an assignment (`=` or `:`) to an `api_key`, `access_token`, `refresh_token`, `password`, `passwd` or `secret`-named key (prefixed names such as `MISTRAL_API_KEY`, `DB_PASSWORD` and `client_secret` included) whose value is a quoted literal of 8 or more characters (spaces allowed) or an unquoted value of 6 or more characters that contains a digit, and an `x-api-key`, `Authorization`, `Proxy-Authorization`, `Cookie` or `Set-Cookie` header with a literal value (for example `Basic <base64>` or `session=<value>`). Exempt as non-credentials: `${...}`, `$VAR`, `%VAR%`, `<...>`, `{{...}}`, all-`x` or asterisk values, values starting with your/example/placeholder/changeme/dummy/redacted/sample, quoted words joined by `_`, `.` or `-` (such as `secret_required_message`), and unquoted types, property chains and calls (`password: string`, `secret: SecretString`, `process.env.SECRET`, `Authorization: authHeader`). The display redactor is broader and unaffected.

Permission rejections follow the ACP specification: a policy or user denial is sent as the selected reject option so the agent continues the turn with the tool refused, while `cancelled` is sent only when the supervisor cancels or closes the run with a request pending. The same applies to a request the supervisor cannot evaluate (no correlated, normalized tool action and path) and to a request that arrives while another is pending: the supervisor selects an offered `reject_once`, else `reject_always`, and falls back to `cancelled` only when no reject option is offered; it never selects an allow option, and the `permission_denied` event records whether the outcome was `rejected` or `cancelled`. `allow_always` and unoffered options are refused, and a cancelled run never reports a completed turn afterwards.

Run directories hold two supervisor-written files that mirror the workspace: `launch-manifest.json` (relative paths, stat fields and SHA-256 hashes of Git-visible files, never file content; owner-only, written atomically, read back only when it is a regular file inside the run directory and its digest matches the recorded one) and `events.ndjson` (opened without following links; if it is replaced by a directory, a symlink or another special file the supervisor stops writing, reports a storage error and never touches the replacement). Patch export reads Git state through a private temporary index with split-index and untracked-cache features disabled, so the source repository's git directory is not modified beyond object storage.

What has and has not been verified against hosted Vibe is listed once, in [compatibility](compatibility.md#unverified-gates).

## Opt-in hosted-test diagnostic metadata

The soak diagnostics described in [functionality](functionality.md#optional-worker-diagnostics-and-overall-soak-budget) preserve fixed launcher stages and bounded Python frame locations only. They never serialize frame locals, call arguments or source lines, and do not expose credentials, prompts, reasoning, native histories or raw ACP/provider payloads. Diagnostic files are private, bounded and fail closed on unsafe paths; diagnostics neither grant tools nor weaken runtime deadlines. Normal execution leaves this diagnostic channel disabled.

Reviewed baseline preparation runs bounded Git with a clean environment that excludes an inherited GIT_INDEX_FILE. Snapshot staging uses only its own new repository index. Offline edit audits check owner-private regular files, safe ancestor permissions, no links, bounds and stable identities; same-account hostile filesystem races are outside this application boundary. Tool argument scope never certifies actual candidate changes.

## Reviewed public environment templates

Baseline preparation refuses sensitive filenames by default. A coordinator may explicitly declare only the root `.env.example` as a reviewed public template using a hash-bound `publicTemplates` manifest entry. This exception belongs to snapshot preparation only; it does not grant the worker access to reserved files or change runtime profiles, canonical allowlists or credential filtering.

Template bytes must be UTF-8 text, pass the credential/sentinel scan, and satisfy the restricted dotenv template parser. Non-sensitive literals are limited to boolean flags and the documented mode/log-level enums. Sensitive assignments require empty values or explicit placeholders; executable expressions and arbitrary secret literals are refused. The declared hash must match the bytes used in the effective baseline, including reviewed overlays. Real `.env`, `.envrc`, nested examples and key files remain refused. Hash approval establishes which bytes were reviewed, not proof that arbitrary content is public.

Preparation diagnostics expose stable codes and stages, never raw exceptions, configuration, file content or environment values. Failed creations retain a private receipt; dry-run refusals create no snapshot directory. Source files, index, refs and allowlists remain unchanged.

## rc.18 reproduced limitations

Policy denial currently selects an offered refusal using label/ID substrings: a misleading allow option can be selected in an offline fake-backend request. Saved metadata can also redirect cleanup between two supervisor-owned fixture worktrees with identical exports. These require private protocol/state access in the demonstrated cases; no shell/network execution or remote exploit was observed. rc.18 documents but does not fix these defects. Shell/network inventory restrictions remain separate protections. Block hosted recovery/soak campaigns pending fixes; do not treat intended policy prose as proof of these uncovered cases. See [current triage](history/reviews/lifecycle-triage-2026-10-09.md) and [recovery plan](lifecycle-recovery-test-plan.md).
