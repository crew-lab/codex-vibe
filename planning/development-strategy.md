# Development strategy

## The goal

Codex hands a task to Vibe, Vibe reviews or implements it, and it works well every time. Nothing else is a goal: no process, gates or decision records for their own sake. Work is chosen by what makes real Codex-to-Vibe runs more reliable and their results better.

## What we work on

1. **Real runs on the Vibe machine.** Build from `main`, install, prepare, and run real reviews and edits through Codex; fix what breaks. The current list of what works and what does not is in the [Handoff](../Handoff.md).
2. **Edit quality.** Real edits failed on content the worker could have got right (named `node:test` cases, test imports, project root, partial writes). The skill's edit brief and the contract now delivered to the worker target exactly these; the [quality pack](../docs/quality-pack.md) shows whether that is enough.
3. **Review quality.** Reviews stay in bounds but cannot search; they read only the files handed as `context_files`. If real reviews still miss code after search-first `context_files`, build the search sidecar ([design](review-search-tool.md)).
4. **Antigravity.** Keep the experimental backend only if it gets used; otherwise remove it.

## Architecture and enforcement points

One run is one worker process (`vibe-app-server` driven over newline-delimited JSON-RPC on stdio when `backend = "app-server"`, or `agy` driven in headless `--output-format stream-json` mode when `backend = "antigravity"`). The run manager (admission, slot, snapshot or worktree, settlement, retention) is the frame both backends plug into; the engine adds the points below, and the coordinator layers sit around both. Preventive points stop a call before it runs; detective points notice it afterwards and interrupt. [Security](../docs/security.md#enforcement-points) is the normative text.

| Point | What happens | Fails closed on |
|---|---|---|
| Preparation | `prepare check` verifies the version-matched kit against the installed candidate, runs the no-inference conformance check once with a fixed fake key and the refusing network observer, and saves a private receipt bound to the candidate bytes, pin manifest, Node, platform and policy (allowed roots excepted). Starting a check invalidates the earlier pass. Readiness reports workspace eligibility, candidate, preparation and an optional expected candidate separately ([preparation](../docs/preparation.md)). | Missing, failed, stale or changed evidence blocks ordinary dispatch; a wrong `expected_candidate` blocks readiness |
| Launch | Pin check and credential lookup (`MISTRAL_API_KEY`, or the macOS Keychain through `/usr/bin/security`) before any process exists; then `vibe-app-server` from the real path the pin hashed, no arguments, own process group, filtered environment, private `HOME`, `VIBE_HOME` and `TMPDIR` in the run directory, and a per-worker loopback managed-config endpoint bound before spawn. The task travels in `turn/start`, never in arguments. | Pin, credential or endpoint failure, before spawn |
| Antigravity launch & policy (`backend = "antigravity"`, experimental, needs `experimental.antigravity = true`) | Probes `agy --version`, verifies `assertNoProjectVibeExtensions` and `assertNoProjectAntigravityExtensions` (rejecting any `.gemini`, `.agent`, `.agents`, `GEMINI.md` or `AGENTS.md` at the workspace root or an ancestor, so this repository itself is not eligible for the Antigravity backend), creates private `antigravity-home` and `antigravity-tmp`, writes `$HOME/.gemini/antigravity-cli/settings.json` (`toolPermission = "strict"`, `enableTerminalSandbox = true`, `allowNonWorkspaceAccess = false`, mode-specific `permissions.allow` and `permissions.deny`), spawns `agy -p <prompt> --mode <plan\|accept-edits> --output-format stream-json --disable-slash-commands --sandbox --print-timeout <N>s` in `workerWorkspace`, parses `status`, `usage`, `num_turns` and `denied_actions`, and removes `antigravity-home` and `antigravity-tmp` on completion/close and restart recovery. The child gets only the selected Google key, `BROWSER=false` and `open`/`xdg-open` shims on `PATH`; preparation accepts only ADR 0008's pinned built-in skills with `builtin: true` and exact global permissions. | Missing `agy` or API key, untrusted workspace extensions, `status: "ERROR" \| "INVALID"`, output limit or timeout |
| Pin | Installed files match the manifest `pin-manifest` wrote on the Vibe machine; `serverInfo.version` equals the installed version after `initialize`. | Any version, `RECORD`, file or unsafe-file mismatch (`VSUP_VIBE_VERSION_UNSUPPORTED`) |
| Session configuration | `agentConfig` with the worker workspace as `cwd`, a supervisor-written profile (`permission = "ask"` plus the reserved-directory and secret-file denylist per tool), `enabledTools`, `disabledTools`, `maxTurns`, no auto-approve, no workspace trust, no roots, no MCP servers; `VIBE_*` settings turn off subagents, shell, connectors, root user and project skills, MCP, telemetry, updates, experiments and session logging, and set `vibe_base_url` to the owned endpoint; thinking off through `config/model/write` before the first turn. | Preventive by construction |
| Read-back | `runtime/read`, `config/effective/read` and `config/read` must show exactly the profile tools, only the bundled skills ADR 0006 permits (with their provenance) and a root skill count of 0, no MCP, connectors, hooks or issues, bypass off, the unified harness (a null selection source accepted), the expected `cwd`, the owned managed-config URL, every setting above, `ask` and the exact denylist per tool, thinking off; repeated after thinking is written and after every handoff. | Any difference or missing field (`readback_mismatch`), before the first turn |
| Approvals | The supervisor answers every `callback/call`: approve only the profile's tool (`file_system.read_file`; for an edit also `file_system.write_file` and `file_system.search_replace`) with the matching effect kind on an in-workspace path that names no reserved directory or secret file; deny everything else within 5 seconds; never a session or permanent approval; each approval bound to one effect by a fingerprint of the shown input. | Deadline, repeated id, malformed callback, wrong session, revoked handler: deny |
| Event validation | Every history entry is classified; reasoning is dropped on receipt. A denied effect is recorded as `tool_denied` and the run continues. An allowed or executed effect is approved only with decision `execute`, type `ask`, source `user`, linked to the handler's approval for the same effect, tool and turn, with an equal fingerprint; null metadata is unapproved. | `turn/interrupt`, then `VSUP_BACKEND_ERROR` with `details.reason` (`unapproved_effect`, `unknown_entry_kind`, `watermark_gap`, `unfinished_effect`, a malformed notification) |
| Handoffs | `session/compacted` and `session/contextCleared` are accepted only from the active session, with a watermark, no open gap, no unfinished effect, no open callback; the new session's history is paged and every settled effect compared with its fingerprint; the read-back repeats; usage totals carry across; the model observation repeats. | `session_handoff_unsafe`, `historical_effect_changed`; a failed re-validation revokes the handler |
| Usage, budgets and observations | No run export exists, so prompt, completion and cached tokens, model calls and cost are rebuilt from `session/statsUpdated` and `runtime/read` with Vibe's pricing formula; the reported model name, alias, thinking and prices are recorded at startup and each handoff; `maxTurns` is Vibe's iteration limit, backstopped by the model-call count; `limits.max_tokens` and `limits.max_cost_usd` interrupt the turn when crossed. Unknown values stay unknown. | `usage_counter_regressed`; `price_unavailable` when a cost ceiling has no price |
| Outcome | Turn status, stop reason and error code, supervisor-detected limits first: `end_turn`, `turn_limit`, `token_limit`, `price_limit`, `refusal` (completed with a warning), `cancelled`; the error-code mapping settled by the owner (`VSUP_AUTH_REQUIRED`, `VSUP_BACKEND_ERROR`, `VSUP_OUTPUT_LIMIT`, `VSUP_RATE_LIMITED`) is in [functionality](../docs/functionality.md#settlement-and-close). An earlier protocol failure outranks a later cancel or deadline. | A limit stop whose final audit could not run (`audit_unavailable`) |
| Reaper | A small Node process in its own group kills the worker's group when the supervisor's PID disappears or the deadline plus a 15-second margin passes; it stays running when a stop cannot be verified, a failed start included. | Nothing; it is the backstop |
| Cleanup | Every stop revokes the handler first, sends `turn/interrupt`, closes stdin (Vibe's clean path, which removes its throwaway store), waits, kills the group if needed, verifies termination, closes the managed-config endpoint, then deletes `child-home`, `vibe-home`, `tmp`, `antigravity-home` and `antigravity-tmp`; a review's snapshot comparison and an edit's export and verified worktree cleanup are the run manager's own checks. | Unverified termination keeps handle, slot, endpoint, worktree and lock (`worker_termination_unverified`); undeletable state is a `private_state_retained` warning |
| Restart | Interrupted runs are marked failed; recovery waits for the old reaper (at most 6 seconds), then deletes the private directories before the server accepts work. Nothing is launched, resumed, replayed, restored or signalled from saved data. | Nothing is trusted from saved state |
| Patch acceptance | An optional contract (exact allowed and required paths, text and hash assertions, required validation IDs) is normalized, hashed and frozen before launch, and evaluated on the committed base plus the exported patch in a private index; bounded saved inputs allow re-verification after cleanup ([workflow acceptance](../docs/workflow-acceptance.md)). Project code never runs. | Missing, unsafe or changed inputs give `incomplete`, never a pass |
| Coordinator decision | `vibe_close` takes an assessment bound to the patch and contract hashes and the coordinator's validations; acceptance needs a fresh automated pass and every required validation passed. Assessments append; a correction keeps the earlier decision. | A hash mismatch or missing validation refuses acceptance |
| Validation | `validation prepare` builds independent baseline and candidate copies from the immutable base and exact patch, with hooks, global Git configuration, lifecycle scripts and fetches off, from a private copy of a populated offline cache; `validation clean` removes only an owned copy whose content still matches ([validation workspaces](../docs/validation-workspace.md)). Project checks stay deliberate coordinator work. | Unsupported profiles are blockers; any doubt about ownership retains the copy |
| Export | `runs verify` and `runs export` write sanitized reports with hashes, optionally the exact patch and projected events; no transcript, reasoning, receipt, history or credential, and private paths replaced. | A patch that trips the credential check is refused, not rewritten |

Around this sit the run controls: strict schemas and exactly five tools; a single-use dispatch grant per start, registered with `task authorize`, bound to the request's digest and checked again just before launch ([ADR 0010](../docs/adr/0010-dispatch-attempt-authorization.md)); the owner-controlled allowlist reread before every readiness check and start; boot-bound settings (`backend`, `paths.*`, `limits.*`, `retention.days`, `version`) that demand a restart; readiness receipts (HMAC, 10 minutes, bound to instance, policy revision, operation, workspace and edit base); one active slot per instance with an owner lock; `--isolated` storage per connection; bounded, redacted, atomically written persistence.

## Risks and dependencies

| Risk | What it would do | How it is held |
|---|---|---|
| Mistral's protocol | `vibe-app-server` has no version field, no official page names it a third-party boundary, and Vibe's earlier headless entry point went from "temporary escape hatch" to removed within days, and 3.0.0 removed three app-server RPCs; a breaking change strands the pinned candidate | Exact pin, drift fails closed; one candidate per Vibe release; the protocol questions go to Mistral as integration notes; the design changes only if the boundary stops being preventive |
| Vibe's own remote configuration | The pinned server refreshes an organization-managed configuration whenever a provider key is present, and a remote layer could override the private settings | The owned loopback endpoint serves a disabled policy and is read back (ADR 0005); there is no remote fallback, so deployments that need organization policy cannot use this profile |
| Codex and Antigravity churn | Codex's tool search and managed worktrees change how the five tools appear; Antigravity ships weekly, has moved its config paths three times and lazy-loads MCP tools | Readiness proves the catalogue on the live connection, and `expected_candidate` proves the build; every claim names the client/CLI version; agy is pinned by version and binary hash |
| Antigravity consumer terms | Running agy headless under a consumer Google sign-in may be outside Antigravity's consumer terms, and forum users report account suspensions, a risk that falls on the account holder | The backend is opt-in and experimental; documentation says to prefer an API key or enterprise authentication and never to use a consumer sign-in from anything that ships; the two-provider data flow is stated |
| Antigravity behaviour unproven | The Antigravity gate is a hook that agy must load, run and obey; if agy skips it, denies nothing on a failed hook, bypasses the proxy or loads project configuration above the workspace, the tool limits are not enforced | Off by default; `prepare check` probes each behaviour through agy and fails the receipt unless it passes; five `UNVERIFIED` gates until the target records them; not for production before then |
| Single platform | macOS Apple silicon only; Linux and Windows code paths exist without evidence | Said in the first paragraph of everything; other platforms are contribution areas, not roadmap |
| Costs barely measured | One hosted review on this build: 14,442 tokens, three model calls, about USD 0.022 by the runtime price estimate; turn count and the underlying model unreported; cost is an estimate | One figure, not a rate; optional ceilings; model and price observations recorded per run; the usefulness log reports rejected runs beside accepted ones |
| Answer quality | Real-project and fixture runs are mixed: the 2.0.1 review reversed two of five cases and its edit missed its contract, while the 2.1.0 fixture edit and both 2.2.0 trials were accepted. A pattern, not a rate; one correct patch was once rejected from an abbreviated summary | Narrow task templates; contracts checked on exported bytes; every answer verified independently; no quality guarantee is made |
| The pin's reach | A matching pin does not prove the code that runs is the code hashed | Documented as drift detection; the wheel-derived manifest later; never called a sandbox |
| Network attribution | A host-only proxy observation cannot say which feature made a request | Every subject request fails the check; the experiments gate stays open until attributable evidence exists |
| Dependency preparation | Offline validation blocks project manager configuration, local dependencies and required build scripts, so not every project can be prepared | Explicit blockers, never implicit script or network permission; reviewed profiles only with authorization |
| Start friction | Every start needs a grant registered with the same install, Node and configuration as the server; a mismatch refuses the start, and before 2.2.0 the error did not say why | `task authorize` selects the server's Node runtime; refused starts name the differing fields; the next remedy is a command generated from the connected server's own bindings (Direction, step 4); a standing authorization is an owner decision recorded here and in the Handoff |
| Antigravity permission bypass | Headless agy auto-denies some calls; `--dangerously-skip-permissions` avoids that but switches off agy's own permission layer, leaving the `PreToolUse` hook as the only tool gate | Opt-in configuration only, boot-bound and in the policy fingerprint, logged at start and on every denial; preparation probes the mode that is configured |

## Lessons

**About Vibe's protocol.** Each of these was a guess that would have broken every real run, caught by reading the tagged source or by the first target check:
- Wire fields are camelCase (`filePath`), because app-server models serialize by alias. The Python attribute name is not the wire name.
- Callbacks and effects name tools `file_system.read_file`, `file_system.write_file` and `file_system.search_replace`; `enabledTools` takes the config names `read_file`, `write_file`, `edit`.
- `read_file` defaults to `always`, and a path allowlist resolves to `always`: both skip the approval callback. The agent profile sets `permission = "ask"` and carries only the denylist.
- Vibe can allow a call without asking (scratchpad paths, session grants, the bypass gate). Only an `execute` / `ask` / `user` effect linked to the handler's own approval counts as approved.
- `vibe-app-server` writes no run export, so usage is rebuilt from events, and counters reset at a context handoff.
- `config/effective/read` has no `max_turns`, and the server redacts MCP `args` and `env`. A read-back that expects either fails every start.
- After a handoff, the new session id is `sessionId`; the old one is `oldSessionId`.
- `config/read.harnessSelectionSource` is null on the unified implementation, the packaged plugin skills are listed even with every skill disabled, and a managed-configuration refresh runs whenever a provider key is present. The source read did not settle these; the installed server did.

**About verification.**
- A fake server encodes what we believe. It proves the client against those beliefs, not against Vibe. Write the fake from source answers with file hashes, reject anything the source contradicts, and expect the target to find what both missed.
- An independent implementation is a strong check. The parallel Codex line and this one each caught errors the other made, and each built pieces the other lacked.
- A cold review before every merge pays for itself. The engine review found a reaper dropped on a failed start, approvals still granted after a stop, and protocol faults hidden by a later cancel, all after a full green test suite.
- Grep-based audits miss behaviour; read the tagged source and record its hashes.

- A real gate finds what tests do not. The first populated-pnpm run found that the lockfile check matched `file:` inside `excludeLinksFromLockfile`, so every pnpm 9 project was blocked, after the whole suite had passed.
- Verify the packaged archive itself, not the tree. The target packet passed release verification, the smoke and every test, and its kit still named other bytes; only an independent inspection of the archive caught it, so packaging now installs the exact archive and compares identities before it reports success.
- Package early and on the machine that will test. `npm pack` runs `prepare` even with `--ignore-scripts`; a cache filled by `npm ci` lacks the metadata an offline tarball install needs, so fill a dedicated cache with `npm cache add` per locked version; and the SBOM's time and namespace make archives differ across machines, so test and publish the same bytes.

**About the 2.1 and Antigravity cold reviews.**
- A hook-based gate needs per-run proof that it ran. A hook file on disk and a read-back of it say nothing about whether the vendor's process called it for a tool call; prove it through the vendor binary, and treat a run whose hook ledger cannot account for its tool calls as failed.
- Denylist filters leak. Dropping reasoning or secrets by a list of known field names misses the next field name; keep what is known safe (an allowlist) and drop the rest.
- Resolve a binary once and execute exactly what was hashed. Looking it up again on `PATH`, or probing its version with the full environment, means what runs need not be what was checked.
- Key budgets by canonical paths. A budget or exclusion keyed by the path as written can be sidestepped by another spelling of the same directory.
- A check that the supervisor runs on its own script is not evidence about the vendor. The first Antigravity no-inference check ran the hook directly; it showed the script works, not that agy uses it.

**About 2.1 and 2.2.**
- Ship no unreachable code on a live path. The deferred correction mode was off everywhere, yet its edits to turn completion and deadline handling broke every one-shot run's finalization; deferring a feature means removing its code from shared paths, not just its entry point.
- Bind what matters, not what is cheap to read. A review grant bound to file timestamps was spent by any editor or build touching the tree; content of the files Git can see is what the review reads.
- An authorization needs diagnostics from the start. A single "invalid or unavailable" hid a Node-runtime mismatch between `task authorize` and the server; per-field hashes name the cause without exposing values.
- Read the vendor's spawn path before trusting a process boundary. Vibe's MCP SDK starts stdio servers in a new session, so a sidecar escapes the worker's process group and the reaper and needs its own lifetime check.
- A source review can retire a design. Vibe 3.0.2's client-provided tools looked like a simpler search route; its own source marks them internal to embedding hosts, so the MCP route stands.
